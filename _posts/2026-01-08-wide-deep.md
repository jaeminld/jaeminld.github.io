오늘은 추천시스템 모델 중에서도 Wide & Deep 모델을 소개한 Wide & Deep Learning for Recommender Systems(2017) 논문을 리뷰해보겠습니다. 해당 연구는 CTR 예측 대회를 진행하며 후보 모델 중 하나였는데, 이해하지 못한 상태에서 쓴 것 같아서 한 번 리뷰해보려고 합니다. 


## Motivation
해당 연구에서 제시한 추천 시스템의 Chellange는 `Memorization`과 `Generalization`입니다. 

`Memorization`은 단어처럼 item의 history, 즉 과거에 발생한 item이나 feature의 조합(occurrence)을 학습하고, correlation을 활용하는 것을 의미합니다.

`Generalization`은 correlation을 활용하여 과거에 본 적 없는 feature 조합도 예측이 가능한 것을 의미합니다. 


### Recommand system 

`Memorizration` 기반 추천의 경우 사용자가 과거에 사용하거나 행했던 action(item)에 밀접한 연관이 있습니다.

`Generalization` 기반 추천은 사용자가 과거에 행했던 action들을 추상화하여 해석함으로써 추천 결과의 다양성을 향상시킵니다.  


### Limitation of Previous Works

일반적으로 대규모 추천 및 랭킹 시스템에서는 Logistic 회귀나 GLM을 사용하는데, 이러한 모델들은 one-hot encoding된 sparse feature를 사용해서 학습됩니다. 여기서 sparse feature라는 것은 [0, 1, 0, 0, 0, 0]과 같이 많은 값이 0이고 소수의 값만 1을 가지는 것이 one-hot encoding vector이기에 sparse feature라고 표현합니다. 

Sparse feature은 cross-product transformation 연산으로 `Memorization`이 가능합니다. 예를 들어서, 특정 사용자가 Netflix를 설치했고, Pandora가 노출된 경우는 AND 연산을 통해 과거의 사용자의 상호작용을 Memorize 할 수 있습니다.  

하지만 `Generalization` 기반 추천에서는 구체적인 예시가 아닌 어떠한 카테고리를 설치했는지의 여부 등 상대적으로 덜 granular feature를 사용하기 때문에 추가적인 feature engineering이 필요합니다. 즉, 학습 과정에서 본 적 없는 조합의 경우에는 학습되지 않기 때문에 generalize에는 한계가 있습니다.


이러한 문제를 해결하기 위해 나타난 모델이 Factorization Machine(FM)과 DNN(Deep Neural Network)입니다. 각 query와 item feature간 저차원의 dense embedding을 학습함으로써 이전에 본 적 없는 query-item pair간의 관계를 generalize할 수 있어 feature engineering의 부담이 적습니다. 


Factorization Machine은 다음 Posting 기회가 생긴다면 해보겠습니다.


하지만 FM과 DNN을 활용하더라도, query-item matrix가 sparse하고 high-rank인 경우에는 효과적으로 학습하는 것이 매우 어렵습니다(사용자의 특정 선호만을 알고 있거나, 특정 사용자를 위한 item인 경우). 이러한 경우에는 query-item 간의 실제 상호작용이 없지만, low-dim dense embedding에서 값이 0이 아닌 값을 가지기 때문입니다. 이렇게 되면 과도하게 generalize되어서 사용자에게 관련성이 적은 추천을 하게 됩니다. 앞서 말한 cross-product feature transformation 을 사용하는 Linear model은 이러한 예외적인 경우에는 적은 파라미터로 학습할 수 있습니다. 


## Wide & Deep Model

<img src="{{site.baseurl}}/assets/img/wide_deep/fig1.png" alt="fig1">

해당 연구에서는 `Memorization`과 `Generalization`을 모두 해결하기 위해 Wide & Deep 모델을 제안합니다. Feature transformation을 포함한 Linear model(Wide)와 Embedding을 이용하는 Feed-forward Neural Network(Deep)를 결합하여 아키텍처를 구성합니다. 

또한, Google Play 스토어 환경에 실제로 적용하여 성능을 평가했습니다. Wide & Deep 모델은 학습 및 서빙 속도도 충분히 빠르면서도 앱 설치 비율을 유의미하게 향상시켰다고 합니다. 

### Recommender System Overview

모델 뿐만 아니라 실제 동작 과정에 관한 설명도 있었는데, 한번 살펴보겠습니다. 

<img src="{{site.baseurl}}/assets/img/wide_deep/fig2.png" alt="fig2">

사용자가 app store에 들어오면, 사용자의 정보와 context feature가 포함된 query가 생성됩니다. 즉, input으로 query가 들어간다면, output으로 사용자에게 추천하는 app들의 list가 반환됩니다. 결과물이 도출되기까지의 과정은 다음과 같습니다. 

1. Retrival
   Google Play에는 수많은 App이 있기 때문에, query가 주어졌을 때 서빙 속도를 고려해야합니다. 이를 위해 query에 맞는 선제적으로 Machine-learning, human-based rule로 N개의 App list를 대략적으로 추출합니다. 
2. Ranking
   Feature가 주어졌을 때($$x$$), 사용자의 action $$y$$를 이용해서 N개의 App에 score를 매겨서 순위를 매깁니다. $$x$$에는 user feature(국가, 언어..)와 context feature(현재 시간, 기기, 날짜..), item feature(앱 출시일, 과거 통계..)가 포함됩니다. 

Wide & Deep 모델은 Ranking에 해당하는 모델입니다. 

### Wide & Deep Component
Wide component는 $$ y = w^T x + b $$ 의 Linear 모델입니다.

- $$y$$: prediction
- $$x$$: $$[x_1, x_2, .., x_d]$$ feature
- $$w$$: model parameter
- $$b$$: bias
  
Wide component에서 사용하는 feature 집합은 raw input과 cross producted feature를 포함합니다. 수식으로는 다음과 같이 나타냅니다:


<div style="text-align:center;">
  $\Phi_k(x) = \prod_{i=0}^d x_i^{c_{ki}}$
</div>


예를 들어서 AND 연산처럼 <한국인, 넷플릭스를 설치 여부>과 같은 feature를 만들 수 있습니다. 이런 경우 binary feature를 명시적으로(explicit) 강조하는 효과를 갖고, 선형 모델에 비선형성을 추가하는 역할을 합니다. 


Deep component는 Feed-Forward Network로 구성됩니다. Categorical feature는 one-hot encoding으로 표현되기 때문에 high-dim sparse vector인데, 이를 low-dim(O(10)~O(100)) embeddig vector로 변환합니다. 


<div style="text-align:center;">
  $ a^{(l+1)} = f(W^{(l)}a^{(l)} + b^{(l)}) $
</div>

- $$l$$: layer number
- $$f$$: activation function(ReLU)


### Joint Training
Wide & Deep은 각 component의 값을 weighted sum하는 방식으로 prediction 값을 만들고, 이 값을 logistic loss 함수에 넣어서 학습합니다. 추론시에 합치는 앙상블 방식과는 달리 각 component는 말 그대로 같이 학습됩니다. 또한, 앙상블 방식은 각 모델이 충분히 커서 성능이 좋아야 하지만, 현재 방식의 Joint training은 Deep component가 갖는 weakness를 보완하는 느낌으로 Wide component를 사용하기에 full-size Wide component가 필요하지 않습니다. 즉, 소수의 cross product transformation feature만이 필요함을 시사합니다. 

최종적인 모델 출력 수식은 다음과 같습니다: 


<div style="text-align:center;">
  $ P(Y=1 \mid x) = \sigma (w^T_{wide}[x, \Phi(x)] + w^T_{deep}a^{(a_{l_f})} + b) $
</div>

- $$P(Y = 1\mid x)$$: 각 app을 user가 설치할 확률

위의 수식은 각 모델에서 나온 값의 출력을 0~1 사이로 prediction으로 만들고, 해당 prediction은 해당 app에 대해서 user가 설치할 확률이라 해석할 수 있습니다. 즉, Wide & Deep 모델은 각 app에 대해 user가 설치할 확률을 예측하고, 시스템에서는 해당 score(prediction)를 Ranking합니다. 


## System Implementation

<img src="{{site.baseurl}}/assets/img/wide_deep/fig4.png" alt="fig4">


Wide & Deep 모델을 학습시킬 때, Wide component에 feature로 설치한 app과 노출된 app 간의 cross-product transformation으로만 구성됩니다. 즉, Wide component는 Deep component 학습시에 부족한 `Memorization`을 보조하도록 학습 설계를 했습니다. Deep component에 input으로 들어가는 categorical feature에서는 32 dim으로 embedding을 만들었고, Dense feature와 모든 embedding의 dim을 concat하면 약 1200dim이 되고, 이를 3개의 ReLU 함수에 통과시킵니다. 

학습 데이터는 약 500 billon 개로, 새로운 학습 데이터로 re-training을 하려면 cost가 굉장히 큰데, 이는 단순히 이전에 사용하던 모델의 가중치 등을 사용하여 새 모델을 학습하는 warm-up start 방식으로 구현했다고 합니다.
